# Phase 7B 第1区間 請求問い合わせ・返金申請受付

## 目的

会員が契約・支払履歴を確認した同じ画面から、対象決済を指定して返金や領収書について問い合わせられるようにする。正式な返金条件や領収書方式が未確定でも、受付と対応履歴を失わずに運用できる状態を対象とする。

## 会員機能

- `/account` の契約・支払履歴から、返金、領収書、支払失敗、解約、その他の問い合わせを送信できる。
- 返金と領収書は本人所有の支払履歴を必須とする。対象決済の所有者はAPIで再確認する。
- 受付は `Idempotency-Key` を必須にし、通信再送で問い合わせを重複作成しない。
- 会員は自分の問い合わせと、受付済み・対応中・解決済みの状態を確認できる。管理者の内部対応理由は返さない。
- 受付は返金承認や領収書発行を意味しないことを画面に表示する。

## 管理機能

- ADMIN+AAL2だけが `/admin/billing` で会員、分類、対象決済、本文、状態、対応履歴を確認できる。
- 受付済みから対応中または解決済み、対応中から解決済み、解決済みから再開へ変更できる。
- 状態変更には理由を必須とし、専用イベントと監査ログへ追記する。
- 問い合わせの会員、対象支払、分類、本文、作成時刻は変更不可とし、本体の削除も禁止する。対応イベントは更新・削除・TRUNCATE禁止をPostgreSQLで強制する。

## 対象外

- Stripeでの全額・一部返金実行
- 返金可否の自動判定
- PDF領収書または適格請求書の発行
- プラン変更、クーポン、試用期間
- 正式価格、返金条件、創設枠、領収書方式の確定

これらは事業・法務方針を確定した後のPhase 7B後続区間で扱う。

## 確認項目

- 他会員の支払いを指定した受付を拒否する。
- 返金・領収書問い合わせでは対象決済を必須にする。
- 同じ冪等キーの再送で1件だけ作る。
- MEMBERとAAL1管理者による管理操作を拒否する。
- 不正な状態遷移を拒否する。
- DBへ直接更新・削除しても履歴保護トリガーが拒否する。
- デスクトップとスマートフォンで横方向にはみ出さない。
