# Phase 6W レース単位の配信結果確認

## 完成条件

- 開催日とレースごとに、対象レース告知、無料パドック速報、レース後検証の全公開版を確認できる。
- 各公開版のWeb掲載日時と、LINE・メール別の送信済み、待機、失敗、対象外件数を表示できる。
- 受信対象の展開前と、展開済みだが対象0件の状態を区別できる。
- レース条件を維持して受信者別の通知配送と試行履歴へ移動できる。
- 集約APIに会員識別情報や通知資格情報を含めず、管理者・運営担当の既存AAL2認可を維持する。

## 実装

- `GET /api/v1/admin/publication-schedules?date=YYYY-MM-DD`
  - 選択日の各レースへ`deliveryResults`を追加する。
  - 通知eventに紐づく告知版または無料速報版、Web掲載日時、event状態、LINE・メール別集計を返す。
  - 選択日外の配送失敗は画面上部の件数へ混在させない。
- `GET /api/v1/admin/notifications?raceId={uuid}`
  - 告知、無料速報、最終予想のいずれかで対象レースに紐づく配送だけを返す。
  - 一覧総数と状態別集計の両方に同じレース条件を適用する。
- `/admin/publication-schedules`
  - レースカード内に公開版別の配信結果を表示する。
  - 「受信者別の詳細」からレース条件付き通知運用へ移動する。
- `/admin/notifications`
  - レース条件で表示中であることを示し、条件解除の導線を表示する。

## 運用上の境界

LINEとメールの件数はアプリが保存した通知配送の結果であり、Provider側の開封や閲覧を示さない。送信失敗は受信者別詳細で試行履歴とコードを確認し、原因を解消してから既存の理由付き再試行を使う。公開版、配送、監査履歴は訂正時も更新・削除せず、新しい版を追記する。外部LINE・Resendとのライブ疎通および本番配信確認は本番接続工程で行う。
