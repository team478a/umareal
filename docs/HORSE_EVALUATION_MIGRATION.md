# 馬評価方式への段階移行計画

状態: ローカル実装・検証完了

確認済み評価結果からのSNS共有候補生成とWeb・LINE・メール通知も現行方式へ移行済み。共有文・共有画像・通知文は馬の評価事実だけで構成し、要確認では生成・送信しない。

## 現行方針

現行の商品は、券種、買い目、組み合わせ、点数、購入金額、資金配分、想定払戻、回収率、プラス収支を新規に入力・公開・集計しない。提供する情報は中心馬、相手候補、注目馬、評価UP馬、評価DOWN馬、危険馬、信頼度、展開予想、パドック診断、選定理由、レース見解、見送り判断とする。

旧機能は将来の事業判断で再検討できるよう休止機能として保持する。過去の公開版、買い目、確定結果、監査履歴は変更・削除しない。旧機能を本番で再有効化する場合は、法的確認、事業方針、API・画面の再審査を別作業とする。

## 実装済み旧機能

- 通常予想の`PredictionVersion.estimatedTotalYen`、`PredictionBet`、`PredictionPerformance`、`BetPerformance`
- WIN5の1点金額、組み合わせ数、想定購入総額
- 通常結果の払戻入力、買い目精算、的中率・回収率
- WIN5結果の公式払戻、想定払戻、想定回収率、完全的中

これらは既存レコードと計算コードを削除せず、現行API・管理画面・会員画面から到達できない状態へ移行する。

## 新形式

- WIN5評価区分は`PRIMARY`、`SECONDARY`、`WATCH`、`RISK`とする。同一馬への複数区分と複数の`PRIMARY`を拒否する。
- 旧WIN5の`CENTER`は`PRIMARY`、`SELECTED`は`SECONDARY`として対応付ける。旧公開スナップショットは書き換えない。
- 通常レースの信頼度は`S`、`A`、`B`、`C`、`SKIP`とする。旧`BET`、`NORMAL`、`SMALL`は新規入出力で使用しない。
- `PRIMARY_TOP2`は中心馬が2着、`PRIMARY_TOP3`は中心馬が3着の状態とする。1着は`PRIMARY_WIN`を使用し、連対・複勝は独立した真偽値で再集計できるようにする。
- WIN5は候補内選出が5件なら`WIN5_ALL_WINNERS_RECOMMENDED`、1〜4件なら`WIN5_PARTIAL`、0件なら`WIN5_MISSED`とする。取消・除外・中止など自動判定できない対象を含む場合は`REVIEW_REQUIRED`とする。

## データ移行

1. 新しい評価列と評価結果テーブルを追加する。
2. 現在のWIN5下書き選択へ`CENTER → PRIMARY`、`SELECTED → SECONDARY`を追加記録する。
3. 旧列、旧テーブル、旧公開スナップショットは残す。
4. APIと画面を新形式へ切り替え、新規の買い目・金額データ作成を停止する。
5. 旧API項目をレスポンスから除外し、無料会員は専用SELECTでメタデータだけを取得する。
6. 物理削除は、本番データ件数、保存義務、再利用方針を確認した別マイグレーションでのみ行う。

## 評価結果通知

- 通常レース結果版とWIN5評価結果版は、それぞれ1件の通知イベントを確定処理と同じDBトランザクションで追加する。DB制約とトリガーが対象の排他性、種別、通知可能な評価状態、同一トランザクション作成を検証する。
- `REVIEW_REQUIRED`は通知対象にしない。通常レースとWIN5は別イベント・別本文として扱い、複合結果状態を作らない。
- 無料会員を含む通知本文とWeb履歴は、対象メタデータ、確認済みの結果概要、版、結果ページURLだけを扱う。馬番、馬名、選定理由、詳細見解、旧買い目・金額情報は含めない。
- 公式訂正では新しい結果版と通知イベントを追記する。既存の結果版、通知イベント、配送、試行履歴は更新・削除しない。

## 料金との区別

会員料金、1日利用料金、Stripe決済額、請求・返金額は馬券購入金額ではないため維持する。買い目関連の金額フィールドだけを休止対象とする。
