# Phase 7A 運用異常の外部通知

## 完成した動作

ワーカーは会員通知の最終失敗、予約公開失敗、発走時刻までに最終予想が公開されなかったレースを検知し、元レコードを変更せず `operational_alerts` へ追記する。異常元IDを含む一意キーで重複を抑止し、同じ異常を再検知しても新しいアラートや外部配送を重ねない。

管理者は `/admin/incidents` で外部通知の有効化、最低重大度、最大10件のメール通知先を理由付きで設定できる。設定変更はrevisionを使って競合を拒否し、ADMIN+AAL2だけに許可する。運営担当は設定を閲覧できる。

未確認アラートはResendメールへ送る。送信はleaseで多重実行を防ぎ、既存の通知再試行回数と待機時間を使って一時失敗を再試行する。外部本文はアラート種別、重大度、安全な要約、検知時刻、管理画面URLだけで構成し、会員メール、LINE subject、予想本文、秘密情報を参照しない。

管理者と運営担当は対応理由を必須にして確認済み、解決済みへ進められる。送信失敗は理由付きで再送待ちへ戻せる。これらの操作は監査ログへ追記し、アラートと外部配送履歴は削除しない。

## 初期方針

- 通知チャネルは既存のResendメールを使用する。
- `CRITICAL`だけ、または`WARNING`以上を選択できる。
- 通知時間帯は制限せず24時間送る。
- 公開期限超過の検知対象は直近24時間に発走した中止以外のレースとする。
- 外部資格情報の発行、送信ドメイン認証、ライブ到達試験は本番接続作業として分ける。

## 運用確認

1. `/admin/settings` でResend送信設定を保存する。
2. `/admin/incidents` で通知先と最低重大度を保存する。
3. テスト環境で警告と重大を発生させ、1回だけ届くことを確認する。
4. 対応理由を入力し、確認済み、解決済み、監査ログを確認する。
