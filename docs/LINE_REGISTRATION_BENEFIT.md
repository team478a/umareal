# LINE無料登録特典

> この文書は現在のLINE新規登録限定V1を記録する。メール確認済み会員を含む通常登録特典への統一は[Phase A監査](MEMBER_CONTENT_REFERRAL_PHASE_A_AUDIT.md)の設計対象であり、Phase Aでは対象判定を変更しない。

## 目的

LINEから無料会員登録を完了した一般会員へ、複数の登録特典動画をアプリ内で案内する。動画ファイルの保管・配信機能は持たず、管理対象のHTTPS動画配信先を利用する。

## 対象者

- `role=MEMBER`かつ、サーバーDBの`registrationMethod=LINE`である有効な会員。
- メール登録後にLINEアカウントを連携した会員は対象外。
- 追加した特典は対象会員全員へ新しい順で表示する。登録時期による出し分けは行わない。
- 画面表示だけでなく、一覧取得と視聴開始APIの両方で対象者を再判定する。
- 対象外の会員には特典設定の有無や動画URLを返さない。

## 会員導線

1. LPのLINE登録ボタンからLINE OAuthへ進み、公式LINEの友だち追加を完了する。サーバーはLINE Login APIで現在の友だち状態を確認し、未追加・ブロック中の場合はシステム会員登録へ進めない。
2. LINE確認後に表示する最後のシステム会員登録画面で、表示名、20歳以上、利用規約、プライバシーポリシーを確認して登録を完了する。
3. `/account?line=registered`へ移動し、登録完了と特典の受取案内を表示する。
4. `/benefit`で追加済み特典のタイトル、説明、未視聴／視聴開始済みを新しい順で確認する。
5. 特典ごとの「動画を見る」を押すと、サーバーが対象者と特典を再確認し、その特典の初回視聴時刻を記録してHTTPS動画配信先を返す。
6. ホーム、マイページ、会員メニューから後日再視聴できる。

動画を自動再生・自動転送しない。LINE Messaging APIで動画URLを直接送信せず、将来通知を追加する場合もログイン後の`/benefit`への案内を使用する。

## 管理

`/admin/benefits`でADMIN+AAL2またはOPERATORが、次を行う。

- 新しい特典のタイトル、説明、HTTPS動画URL、追加理由を入力して追加する。
- 追加済み特典の一覧、追加日時、版番号、最終更新、特典ごとの視聴開始済み会員数を確認する。
- 登録内容に誤りがある場合は、対象の特典だけをrevision付きで編集する。
- 対象会員の総数と特典件数を確認する。

追加した特典は一覧へ残し、V1では削除・公開停止操作を提供しない。動画URLは監査ログへ保存しない。管理画面は個々の視聴会員や個人情報を表示しない。

## API

現在使用する複数特典API:

- `GET /me/free-benefits`: 対象会員へ特典ID、タイトル、説明、追加・更新日時、特典ごとの初回視聴日時を返す。動画URLは返さない。対象外には空の一覧を返す。
- `POST /me/free-benefits/:benefitId/view`: 対象者と特典を再確認し、動画URLとその特典の初回視聴日時を返す。再送しても初回視聴日時は変わらない。
- `GET /admin/free-reports/benefits`: 管理用の特典一覧、対象会員総数、特典ごとの視聴開始済み会員数を返す。
- `POST /admin/free-reports/benefits`: 新しい特典を追加する。
- `PATCH /admin/free-reports/benefits/:benefitId`: revisionを照合し、指定した特典だけを更新する。

`GET/PATCH /admin/free-reports/benefit`、`GET /me/free-benefit`、`POST /me/free-benefit/view`は、旧画面や段階的配備との互換性のため`id=global`の既存特典を扱う。新しい画面は複数形APIを使用する。

## データと移行

- `free_member_benefits`は特典ごとに1行を持つ。既存の`id=global`行は削除せず、最初の特典としてそのまま利用する。
- 新しい特典IDは個人情報を含まないUUIDを使用する。
- `free_member_benefit_views`は会員・特典ごとの初回視聴日時を保持し、`(userId, benefitId)`一意制約でAPI再送による重複を防ぐ。
- 既存の`REGISTRATION_BENEFIT_VIEWED`行動イベントは`id=global`の視聴履歴として非破壊で移行する。
- `member_journey_events.REGISTRATION_BENEFIT_VIEWED`は「登録特典を1件以上視聴開始した」という既存ファネル指標として維持する。
- migrationは既存特典、既存視聴履歴、会員データを削除しない。
- 外部配信先のURLを受け取った対象会員による共有までは防げない。強い配信制限が必要な場合は、動画配信事業者の署名付きURLやドメイン制限を別フェーズで検討する。

## 確認項目

- 未認証は一覧取得・視聴開始とも拒否される。
- メール登録会員とスタッフは動画情報を取得できない。
- LINE登録会員だけが複数特典の概要を取得し、個別の視聴開始時だけ動画URLを取得できる。
- 特典追加後、既存特典と新しい特典の両方が一覧に残る。
- 1件を編集しても、他の特典の内容やrevisionが変わらない。
- 同じ特典の視聴開始APIを再送しても視聴行と日時が増えない。
- 別の特典は独立して未視聴／視聴済みを記録する。
- 管理APIと会員APIへメール、LINE subject、認証情報を追加しない。
- desktop/mobileで長いタイトル、説明、URL、ボタンが横にはみ出さない。
