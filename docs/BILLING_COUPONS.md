# 料金プラン管理・クーポン V1

## 対象

既存の創設会員、通常月額、1日利用を対象に、ADMIN+AAL2が価格、新規販売可否、クーポンを管理する。プラン区分、閲覧権限、Stripe Productを任意追加する機能は含めない。

## 管理操作

- `/admin/settings`: 3プランの税込価格、各プランの新規販売可否、創設会員上限、支払猶予、全体購入停止を理由付きで保存する。
- `/admin/billing`: クーポンを発行し、決済中件数と利用済み件数を確認し、理由付きで新規利用を停止する。
- 発行時にコード、管理用名称、定率または定額、月額の初回のみまたは継続、対象プラン、開始・終了、任意の全体上限を固定する。発行後の条件変更は行わない。

## 会員操作

`/plans`で申込プランと対象日を選び、任意のコードを適用する。APIが対象、期間、利用回数、上限、管理価格から割引を再検証し、画面へ通常金額、割引額、今回支払額を返す。コードを入力したまま未適用の場合は申込を開始しない。

同じ会員は同じクーポンを1回だけ利用でき、複数クーポンは併用できない。初回のみの月額クーポンは初回請求だけ、継続クーポンはStripe Subscriptionの後続請求にも適用する。1日利用では期間区分にかかわらず対象決済1回へ適用する。

## 整合性

`billing_coupons`が発行条件、`billing_coupon_redemptions`が会員単位の予約・利用履歴を保持する。`billing_checkouts`は通常金額、割引額、今回支払額、月額継続金額、クーポンを固定する。会員・クーポンの一意制約、Checkout・支払の一意な関連、クーポン単位のadvisory lockで上限超過と二重利用を防ぐ。

Stripeでは既存Priceを通常料金の正として照合し、サーバーが算出してCheckoutへ固定した円単位の割引額からStripe Couponを冪等作成する。これにより、定率割引でもゼロ小数通貨の丸め差で内部申込額とStripe請求額がずれないようにする。Checkout完了Webhookで予約を使用済みにする。支払後に権限付与が要確認となった場合も使用済みを維持し、返金や管理者レビューで自動復活させない。

## 停止

停止後の新規プレビューと新規Checkoutは拒否する。停止前に開始したCheckoutは固定済み条件を維持する。停止、発行、価格・販売設定の変更は監査ログへ記録する。

## 本番前確認

- Stripe test modeで定率、定額、初回のみ月額、継続月額、1日利用を実決済せずに確認する。
- 初回Invoiceと更新Invoiceの金額、署名付きWebhook、重複Webhook、Checkout期限切れを確認する。
- 正式価格、割引表示、キャンペーン規約、返金時にクーポンを戻さない方針を事業・法務担当が承認する。
- 本番DB migrationとライブStripe設定は本実装とは別の承認で実施する。
