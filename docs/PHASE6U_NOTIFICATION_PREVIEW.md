# Phase 6U 予想レース告知の配信前確認

## 完成条件

- 即時告知と予約告知の前に、次の告知版、対象会員数、予定配送数、LINE・メール別件数、本文、JSTの配信時刻を確認できる。
- プレビュー取得だけでは告知版、通知event、配送、監査履歴を作らない。
- 無効会員、カテゴリ停止、未確認メール、配信拒否、LINE未連携・ブロック、停止中チャネルを実配送と同じ条件で扱う。
- API応答に会員ID、メールアドレス、LINE subject、資格情報を含めない。
- スマートフォンで横方向にはみ出さず、「確認してから告知／予約」の順で操作できる。

## 実装

- `GET /api/v1/admin/notifications/previews/race-announcement`
  - `raceId`必須、予約時だけ`scheduledAt`を指定する。
  - ADMIN+AAL2またはOPERATORに限定する。
  - 発走時刻以降、終了・中止レースを拒否する。
- `/admin/races`
  - 理由を入力後、配信内容を取得し、確認画面から即時告知する。
- `/admin/publication-schedules`
  - 対象レース告知は予定時刻を含む確認画面から予約する。
  - 無料速報の既存予約フローは維持する。

## 運用上の境界

表示人数はプレビュー取得時点のスナップショットであり、宛先の固定や送信保証ではない。ワーカーは配送展開時と送信直前に最新の会員状態、通知設定、閲覧権限、チャネル緊急停止を再確認する。外部LINE・Resendへのライブ疎通と本番配信は別工程で行う。
