# Phase 5L バックアップ・復元確認

## 実装範囲

`pnpm db:backup:verify` は `AUTH_PROVIDER=local`、非production、`127.0.0.1:55432/keiba` の条件を全て満たす場合だけ動作する。PostgreSQLを安全停止してデータディレクトリを `.local/backups/<backupId>/data` へ物理コピーし、全ファイル名と内容からSHA-256を計算する。

バックアップは `.local/restore-verification` の固定配下だけへ複製し、元DBと異なる `127.0.0.1:55433` で起動する。復元後は適用済みマイグレーション数、会員・レース・予想公開版・操作履歴・通知イベント件数、予想公開版・印・買い目・操作履歴の不変化トリガーを元DBと照合する。検証用DBを停止してそのディレクトリだけを削除し、元DBを再起動する。

最後の結果は `.local/backups/status.json` に保存する。`GET /admin/backups/status` と `/admin/backups` はADMIN+AAL2だけが閲覧でき、DB資格情報、絶対パス、ログ内容を返さない。管理画面からプロセス実行は行わない。

## ローカル検証結果

2026年9月13日のPhase 5M後の再実行では、約232 MB、1553ファイルの物理バックアップを隔離復元した。19件のマイグレーション、退会記録を含む5つの必須トリガー、主要5テーブルの件数が一致し、検証用ディレクトリの削除と元DBの再起動を確認した。

## 本番との境界

ローカル物理コピーは未暗号化で `.gitignore` 対象に保存する。本番では利用するDBサービスに合わせ、暗号化、別拠点保管、世代・保持期間、自動実行、監視、RPO/RTO、復旧責任者、実環境での定期復元試験を決める必要がある。このスクリプトを本番DBへ向けることはできない。
