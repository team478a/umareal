# WIN5 Phase 5 公開フロー検証

## 第1区間の目的

管理者が実際の画面だけを使い、WIN5紙面の準備から初版公開まで完了できることをPCとスマートフォンで継続検証する。

## 完了範囲

- WIN5予想枠を作成する。
- 全体総評と公開設定を保存する。
- 対象日の5レースを指定する。
- 各レースで中心馬と相手候補、選定理由、展開見解、短評を保存する。
- 5レースが揃った状態で公開内容を確認し、初版を公開する。
- 公開版、対象5レース、各レースの評価馬がDBへ保存されたことを確認する。
- PCとスマートフォンで横方向の画面崩れがないことを確認する。
- 有料会員が公開紙面と公開履歴を閲覧し、通知履歴から紙面へ移動できることを確認する。

## 検出して修正した不具合

Webの同一オリジンAPI中継が`PUT`を公開していなかったため、WIN5の対象レース保存が実画面ではHTTP 405になっていた。API自体の統合試験はAPIへ直接接続するため、この欠落を検出できていなかった。

中継へ`PUT`を追加し、ブラウザから5レースを保存して公開するE2Eを回帰試験に追加した。

## 第2区間: セキュリティ境界

次の拒否境界を専用のAPI・DB統合試験として追加した。

- 匿名利用者と一般会員はWIN5管理APIを利用できない。
- 管理者でもAAL1では操作できず、担当外の予想担当は対象商品の詳細、候補レース、確認、公開へ進めない。
- クライアントが`role`を送信しても権限を取得できない。
- 公開前確認IDは、確認した商品、操作者、下書き内容、有効期限に拘束される。
- 無料会員、匿名利用者、期限切れ会員、提供対象外プランには、評価馬、馬名、選定理由、展開見解、短評、全体総評を返さない。
- 有効期間とプラン別提供設定の両方を満たした場合だけ有料紙面を返す。

権限を持たない一般会員には`MFA_REQUIRED`ではなく`FORBIDDEN`を返し、二段階認証を追加すれば操作可能になるような誤案内を防止した。

## 第3区間: 負荷試験と開催日リハーサル

次を自動化し、手順を`docs/WIN5_LOAD_AND_RACE_DAY_REHEARSAL.md`へ固定した。

- 同じ公開前確認IDへの8件同時公開で、初版と通知イベントが各1件だけ作られることを統合試験で確認する。
- 匿名、無料会員、有料会員から合計90件を並列閲覧し、HTTP成功と`METADATA`/`FULL`境界を確認する。
- 公開APIだけを対象とする読取専用負荷試験コマンドを追加し、件数、同時数、p95、許容エラー率を環境ごとに変更できるようにする。
- 前日準備、初版・訂正版公開、通知、当日パドック、結果確定、異常系、証跡、本番移行判定を開催日リハーサル手順として定義する。

## 残区間

- ステージング環境での負荷試験実測と、担当者参加の開催日リハーサル
- 本番環境への配備と実運用確認（別承認）
