# WIN5追加開発 Phase 1 設計変更

実装状況: Phase 1の設計とPhase 2の入力・公開機能は完了。会員紙面、閲覧権限、1日利用開始時刻はPhase 3、通知・結果・成績はPhase 4で実装する。

## 目的と互換性

既存の1レース単位のパドック直前予想を維持したまま、5レースを1商品として扱う `WIN5_PREVIEW` を追加する。既存の `predictions`、`prediction_versions`、公開API、結果集計は `PADDOCK_RACE` 相当として挙動を変えない。WIN5は単一の `raceId` に所属させず、独立した集約ルートとする。

Phase 1は設計と仕様更新だけを対象とし、データベースやアプリケーションの挙動は変更しない。

## 現在の実装との差分

| 領域 | 現在 | WIN5追加後 | 互換性方針 |
| --- | --- | --- | --- |
| 予想単位 | `predictions` が1レースと1対1 | 1商品が順序付き5レースを持つ | 既存テーブルを移行・改名しない |
| 入力 | 担当レースの評価・印・通常馬券 | 5レースの選択馬、中心馬、戦略、理由 | WIN5専用ワークスペースを追加 |
| 公開 | レース発走時刻を締切に公開版を追記 | 5レース中で最も早い発走時刻を締切に商品版を追記 | 共通の追記・監査原則を再利用 |
| 閲覧 | レース詳細でFREE/PAIDを版ごとに判定 | 前日・当日のWIN5紙面を商品単位で判定 | 公開APIを分離し情報漏えいを防ぐ |
| 1日利用 | JST対象日0時から翌日0時 | 初版の実公開時刻から翌日0時。商品がなければ対象日0時 | Phase 3で遅延有効化へ移行 |
| 通知 | レース告知、無料速報、パドック予想 | WIN5公開・訂正・結果確定を追加 | 既存outboxと配送基盤を拡張 |
| 結果 | レース結果と通常馬券公開版別精算 | 5レースの勝ち馬とWIN5商品版を固定して判定 | 通常馬券成績と別集計 |
| SNS | 自動生成なし | 結果確定後だけ共有文・画像を生成 | 自動投稿は行わない |

## 採用データ構造

実装時のPrisma名は既存規約に合わせる。物理名は次を基準とする。

### `prediction_products`

- UUID主キー
- `type` は当面 `WIN5_PREVIEW` のみ
- JST運用日を表す `targetDate`
- タイトル、担当専門家、状態、公開範囲、公開予定時刻、初版実公開時刻
- `closeAt` は対象5レースの最小 `startsAt`
- 全体信頼度、総評、下書きrevision、作成・更新時刻
- `type + targetDate` を一意にし、同じ開催日のWIN5を重複作成しない

### `prediction_product_races`

- 商品と既存 `races` を結ぶ
- `legNumber` は1〜5
- レース信頼度、`NARROW / NORMAL / SPREAD`、選択理由
- `productId + legNumber` と `productId + raceId` をそれぞれ一意にする
- レースの `raceDate` は商品の `targetDate` と一致させる

### `prediction_product_selections`

- 商品対象レースと既存 `race_entries` を結ぶ
- `selectionType` は `CENTER / SELECTED`
- 中心馬も選択馬として数え、対象レースごとに中心馬をちょうど1頭とする
- `productRaceId + entryId` を一意にし、表示順を保持する
- 公開時には馬ID、馬番、馬名をスナップショットへ凍結する

### `prediction_product_previews`

- 操作者、商品、下書きrevision、入力全体のハッシュ、次版番号、有効期限を保持する
- 既存公開前確認と同じく15分で失効し、確認後のレース、出走馬、担当、選択、公開履歴変更を検出する

### `prediction_product_versions`

- 商品、版番号、初版・訂正版状態、内容全体のJSONスナップショット
- 公開者、公開時刻、締切時刻、訂正理由、直前版ID、作成トランザクションID
- `productId + versionNumber` を一意にする
- UPDATE、DELETE、TRUNCATEをPostgreSQLトリガーで拒否する
- 結果判定対象は締切までに公開された最新の版とし、結果へ版IDを明示的に保存する

### WIN5結果

Phase 4では `win5_result_drafts` と追記専用 `win5_result_versions` を使う。確定結果版は、判定対象の商品公開版、5レースそれぞれの確定レース結果版、的中脚数、完全的中、公開時の組み合わせ数・想定購入額、公式払戻額、想定払戻額、想定回収率、確認者、確認時刻、集計ルール版を固定する。

通常馬券の `prediction_performances` へ混在させない。ダブル的中は専用レコードへ、使用したWIN5結果版、各パドック予想版と結果版、日次集計値、判定時刻を保存する。

## 計算と公開規則

- 組み合わせ数は5レースの選択頭数の積とする。中心馬は選択頭数に1回だけ数える。
- 想定購入総額は `組み合わせ数 × 1点当たり金額`。金額は整数円で、初期値100円を管理設定に保存する。
- 警告上限も管理設定に保存する。上限超過は警告とし、公開を禁止するかは保留とする。
- 5レースが揃い、各レースに選択馬と中心馬があり、対象順とレースが重複しない場合だけ公開できる。
- 締切は5レースの最新情報から算出した最小発走時刻。プレビュー時と公開確定時の両方で再計算する。
- 初版・訂正版とも `now < closeAt` の場合だけ公開できる。管理者も例外にしない。
- 当日のパドック評価や結果をWIN5公開版へ書き戻さない。差異説明はパドック予想側の独立した表示文として扱う。
- 無料会員向けレスポンスは商品ID、対象日、タイトル、公開状態・時刻、対象5レースの競馬場・番号・発走時刻と、公開設定で許可された全体信頼度だけを返す。選択馬、中心馬、馬番、理由、金額、総評、訂正理由は返さない。

## 1日利用

- 月額・創設会員は有効な既存entitlementでWIN5とパドック予想を閲覧できる。
- 1日利用の支払がWIN5初版公開前に完了した場合、支払済みの待機状態として保存し、初版公開トランザクションまたは有効化ジョブが `startsAt=初版publishedAt` の有限entitlementを作る。
- 対象日のWIN5商品が存在しない場合は、対象日JST 00:00を開始時刻にする。
- 終了は対象日の翌日JST 00:00を排他的終了時刻とする。
- 商品が未公開のまま対象日を迎える場合の扱いは公開遅延警告を出し、対象日00:00で有効化するか返金対象にするかを事業判断として保留する。

## 権限

| 操作 | ADMIN | OPERATOR | 担当EXPERT | MEMBER |
| --- | --- | --- | --- | --- |
| 商品・対象レース設定 | AAL2 | AAL2 | 不可 | 不可 |
| 選択馬・理由の入力 | AAL2 | AAL2 | AAL2かつ商品担当 | 不可 |
| プレビュー・初版公開 | AAL2 | AAL2 | AAL2かつ商品担当 | 不可 |
| 訂正版公開 | AAL2 | 方針確定まで不可 | 方針確定まで不可 | 不可 |
| 結果取込・確認 | AAL2 | AAL2 | 不可 | 不可 |
| 閲覧 | 全版 | 全版 | 担当商品の全版 | 契約と公開範囲に応じる |

ロール、AAL、担当者はすべてサーバー所有データから判定し、リクエスト本文やSupabase user metadataを信用しない。管理用URLでも担当EXPERTに管理権限を与えず、専門家用入力APIを分離する。

## APIレスポンス境界

- 管理・専門家レスポンスは認可後に編集用データを返す。
- 有料会員レスポンスは有効期間、対象日、公開範囲、公開時刻をすべて満たした版だけ本文を返す。
- 無料・未認証レスポンスは専用DTOを組み立て、機密フィールドを取得後に削る方式を採用しない。
- 旧版も各版の公開範囲と当時の権利条件を独立判定する。
- 通知本文は会員区分別にサーバーで生成し、無料通知へ馬番、選択馬、中心馬、理由、買い目を含めない。

## 保留事項

以下は開発を止めず、安全側の既定値または `REVIEW_REQUIRED` で進める。

- 無料会員へ結果確定後に開示する項目
- 取消、除外、中止、返還時の組み合わせ数・購入額・払戻の正式ルール
- 組み合わせ警告上限を超えた場合に公開自体を禁止するか
- 訂正版を広告用の代表成績へ採用する規則
- OPERATORまたは担当EXPERTによる訂正版公開の可否
- WIN5商品が未公開のまま対象日を迎えた支払済み1日利用の扱い

未確定の例外結果は `REVIEW_REQUIRED` とし、結果確定、的中表示、SNS画像生成を禁止する。無料会員の結果表示は項目確定まで開催日、対象レース、結果確認状態だけとする。

## 実装順

1. Phase 1: 本設計、仕様、ERD、API契約を確定する。
2. Phase 2: 商品・5レース・選択馬・計算・プレビュー・公開版・訂正版・監査を実装する。
3. Phase 3: 会員紙面、前日・当日導線、月額・1日利用、無料DTOを実装する。
4. Phase 4: 通知、結果、WIN5成績、ダブル的中、SNS共有を実装する。このリポジトリの現在の実装許可範囲外のため、着手前に範囲を更新する。
5. Phase 5: 全E2E、負荷、セキュリティ、改ざん防止、開催日リハーサルを実施する。

各Phaseで既存パドック入力・公開・通常馬券結果・課金・通知の回帰テストを含め、typecheck、lint、test、buildをすべて実行する。
