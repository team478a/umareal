# JRA-VAN未接続 実運用リハーサル結果

## 結論

判定は **CONDITIONAL GO** とする。

JRA-VAN/JV-Link/外部競馬データProviderを一度も接続しない状態でも、管理画面を中心に、開催日登録から結果確定・成績反映・監査確認まで完走できた。単一または少数の対象レースを手動運用する初期運用は可能である。

一方、12レース・各18頭を1人で全件手入力する運用は、出走馬登録、暫定Horse Identity確認、結果入力の反復量が大きい。CSVは必須ではないが、フルカードを継続運用する場合は、入力分担または確認付き一括入力を前提にする必要がある。

## Basic Guide安全確認

手動登録馬には性齢、斤量、騎手、調教師、過去走、オッズ等を登録しなかった。公開されたBasic Guideは次を満たした。

- 「詳細が未登録」「データ不足を成績不振とは扱わない」と明示した。
- 登録済みのレース概要、馬番、馬名、出走状態だけを整理した。
- 架空の過去成績、騎手、調教師、オッズ、馬場適性、勝率を生成しなかった。
- AI独自の印、買い目、購入金額、的中保証を生成しなかった。
- Assessment、Prediction、三国谷コメント、会員情報を事前Factへ混入しなかった。
- 外部AI/API通信を行わなかった。

### 人手時間の評価

実際の担当者は出馬表・パドック映像・公式結果との照合を行うため、自動操作時間は運用時間として使用できない。画面操作数、読み合わせ、確認時間を加味した目安は次のとおり。

- 6頭のリハーサル相当：およそ12〜20分。
- 18頭の1レース：およそ25〜45分。約339操作、約290入力項目相当。
- 12レース・各18頭をすべて同じ深さで手入力：およそ5〜8時間に加え、実際のパドック観察時間が必要。

レース枠だけなら「かんたん一括登録」で12レースをまとめられる。しかし、216頭の出走馬、暫定Identity、結果は頭単位の確認が必要であり、1人がレース間隔内に全件処理する運用は現実的ではない。対象レースを限定する、複数担当者で分担する、または確認付きCSV/一括入力を使用する必要がある。

## 入力負担の確認

### 同じ情報の再入力

- レース基本情報を予想・結果画面で再入力する必要はない。
- 馬名や馬番を予想・結果画面で再入力する必要はない。
- 操作理由は監査要件のため工程ごとに必要で、簡易出走馬登録とIdentity確認では馬ごとに反復する。
- 結果は各馬について着順、人気、確定単勝の3項目を手入力する。

### UUID等の技術情報

- UUIDを担当者が入力する必要はない。
- 簡易登録時のHorse IDはサーバーが生成する。
- 暫定馬確認画面にはUUIDが表示される。入力は不要だが、運営担当者には技術情報であり、画面上の優先度は低い。

### CSV依存

- 開催日、レース、出走馬、予想、Basic Guide、結果、監査の全工程をCSVなしで完走した。
- CSVは必須ではない。
- ただし12レース規模では、出走馬と結果の確認付きCSVが実務上有効である。

### エラー時の復旧

- パドック入力は端末一時保存、自動再送、競合比較、再同期の導線がある。
- 予想公開前に下書きとプレビューがあり、公開後は新しい版で訂正する。
- 結果は下書きと確定が分離され、確定版は上書きされない。
- CSV取込を使う場合も差分プレビューと確定操作が分離される。
- レース・出走馬フォームの未送信値はページ離脱後に復元されないため、長時間入力には注意が必要。

## 発見した問題

### BLOCKER

なし。

### HIGH

1. **フルカードの頭単位入力負担**  
   12レース×18頭では、出走馬216件、Identity確認216件、結果648項目が発生する。画面だけで処理可能だが、単独担当者による継続運用には重い。

2. **全頭パドック入力の時間制約**  
   1頭につき5指標、総合変化、短評を入力する。スマートフォン表示と自動保存は正常だが、18頭を発走前の短時間で入力し、さらに最終評価を公開するには事前の役割分担と実機練習が必要。

### MEDIUM

1. **暫定Identity確認がグローバル一覧の先頭にある**  
   未確認馬が蓄積すると、対象レースの編集領域へ到達する前に長い一覧が表示される。レース単位の絞り込みがなく、他開催日の未確認馬と混ざる。

2. **レース管理の初期読込が全予想担当者の取得完了を待つ**  
   ローカルDBに検証用担当者が数百件ある状態では、ページング取得完了までデータ取得方式やレース一覧の表示が5秒を超える場合があった。通常の少人数運用では問題化しにくいが、不要アカウントを含めた全件取得への依存がある。

3. **AIガイド対象レース選択は最新500件固定**  
   今回の対象日は一覧内にあり正常だったが、長期運用後に古いレースを訂正確認する用途では一覧から外れる可能性がある。

### LOW

1. 暫定馬確認画面に生のUUIDが表示され、非技術担当者にはノイズになる。
2. 簡易登録理由、Identity確認理由を各馬で繰り返し入力する。
3. `発汗・落ち着き`が1項目のため、将来分析では発汗と落ち着きを分離できない。今回の事前AI Factには使用していない。

## UI評価

### パドック予想

- レース選択→馬選択→パドック入力→保存状態→全頭確認→最終評価→公開前確認→公開の順序は理解できる。
- 390×844で横方向のはみ出しは発生しなかった。
- 馬番ボタン、前後移動、保存状態、未入力馬表示により進捗を確認できた。
- `本命/対抗/単穴/連下/穴/危険馬`は最終評価、`UP/DOWN`はパドックの総合変化として分離されている。
- 自動保存待ちを確認せず次へ進むと不安が残るため、実運用マニュアルでは「保存済み」を確認してから最終公開へ進むよう明記すべきである。

### Basic Guide

- 生成、Fact/Evidence、検証、確認、公開が1画面にまとまっている。
- データ不足の説明は会員にも明確で、成績不振との誤認を防いでいる。
- 名称はAIレースガイドのままだが、カード内で「Basic Guide（固定テンプレート）」「外部AIによる生成や予測は行っていません」と明示される。

## 本番運用可否

### 運用開始可能な範囲

- 三国谷氏の対象レースを限定した初期運用。
- レース・出走馬を前日までに登録できる運用。
- 当日はパドック評価と最終予想公開へ集中する運用。
- 結果登録をレース後または開催終了後に別担当が行う運用。
- Basic Guideは固定テンプレートとして人が確認後に公開する運用。

### 条件

1. 12レースすべてを単独担当者が全頭・全工程入力する前提にしない。
2. 出走馬登録と結果登録は前後工程へ分離し、必要なら既存CSVを使用する。
3. パドック公開担当はスマートフォン実機で「保存済み」確認まで事前練習する。
4. 暫定Identityの確認責任者と確認タイミングを決める。
5. JRA-VAN未接続を正常状態として扱い、Basic GuideをData Guideと誤認させない。

以上の条件を満たす場合、JRA-VAN未接続の限定初期運用は開始可能である。
