# JRA-VAN未接続 実運用リハーサル結果

## 結論

判定は **CONDITIONAL GO** とする。

JRA-VAN/JV-Link/外部競馬データProviderを一度も接続しない状態でも、管理画面を中心に、開催日登録から結果確定・成績反映・監査確認まで完走できた。単一または少数の対象レースを手動運用する初期運用は可能である。

出走馬登録、同名候補のない暫定Horse Identity、結果入力は、12レース各18頭でもレースごとの貼り付け・選択・プレビュー・確定へ短縮した。同名候補がある馬は個別確認を維持する。CSVは必須ではないが、フルカードを継続運用する場合は当日の全頭パドック評価を中心に入力分担を前提にする必要がある。

## Basic Guide安全確認

手動登録馬には性齢、斤量、騎手、調教師、過去走、オッズ等を登録しなかった。公開されたBasic Guideは次を満たした。

- 「詳細が未登録」「データ不足を成績不振とは扱わない」と明示した。
- 登録済みのレース概要、馬番、馬名、出走状態だけを整理した。
- 架空の過去成績、騎手、調教師、オッズ、馬場適性、勝率を生成しなかった。
- AI独自の印、買い目、購入金額、的中保証を生成しなかった。
- Assessment、Prediction、三国谷コメント、会員情報を事前Factへ混入しなかった。
- 外部AI/API通信を行わなかった。

### 人手時間の評価

実際の担当者は出馬表・パドック映像・公式結果との照合を行うため、自動操作時間は運用時間として使用できない。画面操作数、読み合わせ、確認時間を加味した目安は次のとおり。

- 6頭のリハーサル相当：およそ12〜20分。
- 18頭の1レース：出走馬・候補なしIdentity・結果の登録は確認付き一括操作で数分に短縮できるが、パドックを含めるとおよそ20〜40分。
- 12レース・各18頭をすべて同じ深さで処理：およそ4〜7時間に加え、実際のパドック観察時間が必要。

レース枠、出走馬、候補なしIdentity、結果は確認付き一括操作を利用できる。同名候補のIdentityと全頭パドックは頭単位の確認が必要であり、特に1人がレース間隔内に全頭パドックを処理する運用は現実的ではない。対象レースを限定するか、複数担当者で分担する必要がある。

## 入力負担の確認

### 同じ情報の再入力

- レース基本情報を予想・結果画面で再入力する必要はない。
- 馬名や馬番を予想・結果画面で再入力する必要はない。
- 操作理由は監査要件のため工程ごとに必要だが、一括簡易登録と候補なしIdentity確定はレース単位の共通理由を使用できる。
- 結果は全頭分を1つの貼り付け欄へ入力し、差分プレビュー後に下書きへ反映できる。

### UUID等の技術情報

- UUIDを担当者が入力する必要はない。
- 簡易登録時のHorse IDはサーバーが生成する。
- 詳細入力時のHorse IDも画面内で生成・保持し、担当者へ表示しない。
- 暫定馬確認・確認済みIdentity画面ではUUIDを表示せず、候補番号、馬名、使用レース数で識別する。API・監査・同時更新検査では内部UUIDを維持する。

### CSV依存

- 開催日、レース、出走馬、予想、Basic Guide、結果、監査の全工程をCSVなしで完走した。
- CSVは必須ではない。
- 12レース規模でも出走馬と結果は貼り付け一括入力で処理できる。正式CSVは任意である。

### エラー時の復旧

- パドック入力は端末一時保存、自動再送、競合比較、再同期の導線がある。
- 予想公開前に下書きとプレビューがあり、公開後は新しい版で訂正する。
- 結果は下書きと確定が分離され、確定版は上書きされない。
- CSV取込を使う場合も差分プレビューと確定操作が分離される。
- レース一括登録、レース・出走馬詳細、出走馬一括簡易登録、結果一括入力は、未送信値を同じ利用者・同じタブ・同じ対象で復元できる。対象revisionが変わった場合は古い入力を復元しない。ファイル選択はブラウザの安全制約上復元しないため、CSV利用時は再選択が必要。

## UI評価

### パドック予想

- レース選択→馬選択→パドック入力→保存状態→全頭確認→最終評価→公開前確認→公開の順序は理解できる。
- 390×844で横方向のはみ出しは発生しなかった。
- 馬番ボタン、前後移動、保存状態、未入力馬表示により進捗を確認できた。
- 6項目まとめ入力は現在の馬だけに反映され、個別調整、総合変化、短評を上書きしない。
- `本命/対抗/単穴/連下/穴/危険馬`は最終評価、`UP/DOWN`はパドックの総合変化として分離されている。
- 自動保存待ちを確認せず次へ進むと不安が残るため、実運用マニュアルでは「保存済み」を確認してから最終公開へ進むよう明記すべきである。

### Basic Guide

- 生成、Fact/Evidence、検証、確認、公開が1画面にまとまっている。
- データ不足の説明は会員にも明確で、成績不振との誤認を防いでいる。
- 名称はAIレースガイドのままだが、カード内で「Basic Guide（固定テンプレート）」「外部AIによる生成や予測は行っていません」と明示される。

## 本番運用可否

### 運用開始可能な範囲

- 三国谷氏の対象レースを限定した初期運用。
- レース・出走馬を前日までに登録できる運用。
- 当日はパドック評価と最終予想公開へ集中する運用。
- 結果登録をレース後または開催終了後に別担当が行う運用。
- Basic Guideは固定テンプレートとして人が確認後に公開する運用。

### 条件

1. 12レースすべてを単独担当者が全頭・全工程入力する前提にしない。
2. 出走馬登録と結果登録は前後工程へ分離し、レース単位の確認付き一括入力を使用する。
3. パドック公開担当はスマートフォン実機で「保存済み」確認まで事前練習する。
4. 暫定Identityの確認責任者と確認タイミングを決める。
5. JRA-VAN未接続を正常状態として扱い、Basic GuideをData Guideと誤認させない。

以上の条件を満たす場合、JRA-VAN未接続の限定初期運用は開始可能である。
