# 残機能の実装計画

対象はアプリケーション機能だけとし、サーバー作成、DNS、外部サービスの資格情報発行、法務文書の確定、本番公開作業は含めない。事業の基本導線である「無料会員登録 → 予想レース告知 → 無料情報配信 → 有料化」を止める不足から順に、一つのゴールとして完成・検証してから次へ進む。

## 現在の優先ゴール: WIN5追加

前日公開の`WIN5_PREVIEW`と当日公開の既存パドック直前予想を2商品として提供する。設計変更のPhase 1と入力・公開のPhase 2は完了し、詳細は`docs/WIN5_PHASE1_DESIGN.md`を参照する。

1. 完了 Phase 1: 現行差分、独立データモデル、権限、公開・締切、1日利用、API境界を確定
2. 完了 Phase 2: WIN5開催、対象5レース、選択馬、計算、プレビュー、初版・訂正版、DB改ざん防止
3. 次 Phase 3: 会員紙面、前日・当日導線、有料・1日利用、無料会員情報制限
4. Phase 4: 通知、結果、WIN5成績、ダブル的中、SNS共有。現在の実装許可範囲外
5. Phase 5: E2E、負荷、セキュリティ、開催日リハーサル

## 完了 ゴール1 Phase 6Y: 無料登録入口のBot対策

公開LPから登録画面へ流入を増やしても、機械的な大量登録が認証基盤とメール配信を圧迫しない状態にする。

- Cloudflare Turnstileをメール会員登録画面へ表示し、APIでSiteverifyを必須実行する。
- 有効化、Site key、暗号化Secret key、準備状態を管理画面で一括管理する。
- actionと公開hostnameをサーバーで検証し、トークン、Secret、Provider応答本文を記録しない。
- ローカル・CIでは外部通信を行わない安全な試験transportを使い、本番では試験transportを拒否する。
- 新規登録停止中は従来どおり停止理由を優先し、LINE登録にはLINE Provider本人確認があるためTurnstileを重ねない。

完成条件は、管理者が設定を保存でき、未回答・不正回答のメール登録を拒否し、正常回答だけが従来の登録処理へ進み、公開準備画面で不足を確認できることとする。

## 完了 ゴール2 Phase 6Z: 管理者の復旧と継続運用

初回管理者がMFA端末を失っても、会員機能を止めずに権限を安全に復旧できる状態にする。

- 単独管理者を避けるため、ADMIN+AAL2が確認済みメール会員を理由付きで管理者へ昇格し、対象者のローカルセッションを失効する。
- Supabaseが利用者向け復旧コードをサポートしないため、主端末とは別管理の予備TOTP要素を採用する。独自コードでAAL2を代替しない。
- 予備要素の登録、ログイン時の選択、理由付き解除、Providerを含む全セッション失効を監査する。
- 有効管理者2名以上、各管理者の主・予備要素を管理画面と本番準備チェックで判定する。

完成条件は、サーバー所有ロールと署名済み`aal2`の境界を維持したまま、別管理者または予備要素で運用を継続でき、解除・再登録の履歴が残ることとする。

## 完了 ゴール3 Phase 7A: 運用異常の外部通知

管理画面を開き続けなくても、配信失敗、予約公開失敗、公開期限超過を運営が把握できる状態にする。

- 既存の失敗状態から運営向けアラートeventを追記作成する。
- 重複抑止、確認済み、解決済みを管理し、元の公開・配送履歴を変更しない。
- 運営通知先と対象重大度を管理画面で設定する。
- 外部通知に会員のメール、LINE subject、予想本文、資格情報を含めない。

初期通知先は既存のResendメールとし、管理画面で最大10件の運営メールアドレスと最低重大度を設定する。24時間送信し、通知時間帯と当番サービスへの拡張は実運用データを見て判断する。

## ゴール4 Phase 7B: 有料化の販売機能完成

無料会員が料金確認から申込、契約確認、解約まで自己完結できる状態にする。

- 既存Stripe Checkoutと継続課金同期を本番販売条件へ合わせる。
- 領収書・請求履歴の導線、返金受付、プラン変更、クーポン・試用の採否を反映する。
- 決済失敗、猶予、解約終了後の表示と問い合わせ導線を完成する。

正式価格、返金条件、創設枠、試用、クーポン、領収書方針は事業・法務判断後に実装する。

第1区間として、事業判断に依存しない請求問い合わせ・返金申請受付を実装済み。会員は本人の支払いを指定して問い合わせ、運営はADMIN+AAL2で受付・対応中・解決・再開を理由付きで管理する。実際の返金実行と領収書発行は後続区間に含める。

## ゴール5 Phase 7C: 成長後の拡張

初期事業の成立を確認した後に着手する。

- CMSによる記事・固定ページ管理
- 外部レースデータ取込と差分更新
- 高度な流入分析、広告費・LTV連携
- 過去予想検索と公開成績表示の拡張

初期公開には含めない。
