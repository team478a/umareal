# Phase 5N 本番準備チェック

## 目的

本番接続へ進む前に、アプリ設定、外部サービス、法務・個人情報、監視・復旧の不足を管理者が一画面で確認できるようにする。設定作業や公開操作は行わない。

## 実装

`GET /api/v1/admin/readiness` はADMIN+AAL2だけに、15項目の状態、根拠、次の対応、関連管理画面を返す。状態は `READY`、`BLOCKED`、`MANUAL` のいずれかで、総合状態は要対応があれば `NOT_READY` になる。暗号化資格情報は有無だけを確認し、値を返さない。公開応答は`packages/domain`の共有ContractでAPIとWebの不整合を検知する。

`/admin/readiness` はスマートフォンでも集計と各項目を縦に確認できる。基盤・認証、外部接続、法務・データ、運用・復旧の4区分から、設定、バックアップ、退会記録、障害対応など既存画面へ移動できる。

ローカル隔離復元は最終成功から7日以内だけ確認済みとする。APIサーバー自身が結果ファイルを読める場合は`READY`、開発端末の結果を管理者が記録した場合は`MANUAL`とし、自動検証と人による証跡を区別する。外部決済はWebhookを含む実装完了まで要対応、本番バックアップは暗号化・別拠点保管・RPO/RTO・責任者を人が確認する項目として扱う。

`GET /api/v1/admin/readiness/local-restore-attestation` と `POST /api/v1/admin/readiness/local-restore-attestation` はADMIN+AAL2専用である。POSTは`pnpm db:backup:verify`が生成した成功JSON、記録理由、7日以内の実行日時、現在の適用済みmigration数、12件の履歴保護トリガーを検証し、既存のappend-only監査履歴へ記録する。バックアップ本体、絶対パス、DB資格情報は受け取らない。記録後も本番サーバーで復元を再現したとは表示しない。

## 制限

設定済みという表示はライブ疎通の成功を意味しない。正式文書、データ利用許諾、外部決済、実Supabase、LINEとメールの実送信、外部監視、本番バックアップは別作業で確認する。画面の自動判定だけで本番公開を承認しない。
