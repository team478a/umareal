# 出走馬の確認付き一括簡易登録

作成日: 2026-10-07

## 目的

JRA-VAN未接続の手動運用で、1レース最大18頭を1頭ずつ登録する反復を減らす。正式CSVを作らなくても、管理者またはレース担当が出馬表を見ながら馬番と馬名を貼り付け、登録前に全頭を確認できるようにする。

## 管理画面の操作

1. `/admin/races`で開催日と対象レースを選ぶ。
2. 「馬番と馬名をまとめて簡易登録」に、1行1頭で`馬番,馬名`を入力する。タブ区切りにも対応する。
3. 「登録内容を確認」で最大18頭のプレビューを表示する。
4. 馬番、馬名、登録後の状態を照合し、一括登録理由を入力する。
5. 「確認したN頭を一括登録」で確定する。

既存の1頭ずつの簡易登録と詳細入力は、追加・訂正用として維持する。

## 保存契約

- APIは`POST /admin/races/:id/entries/manual-batch`を使用する。
- 入力は`entries`、現在の`revision`、監査用の`reason`で構成する。
- 同じリクエストの再送は既存の`Idempotency-Key`契約で同じ結果を返す。
- 登録済み馬番、重複馬番、重複馬名、不正な行、19頭以上は確定前に拒否する。
- 18頭のHorse、暫定Identity、RaceEntry、Race revision、監査ログを1トランザクションで保存する。一部成功は許可しない。
- 監査操作は`MANUAL_ENTRY_BATCH_CREATE`としてレース単位で1件記録し、各RaceEntryとIdentityを追跡できる。

## Horse Identity

- 馬名だけを恒久Identityとして使用しない。
- Horse UUIDと`MANUAL`外部Identityはサーバー側で生成する。
- 同名の既存Horseがあっても自動統合しない。`POSSIBLE_DUPLICATE`として人の確認へ回す。
- 枠番、性齢、斤量、騎手、調教師等を推測せず、未確認のまま保存する。
- 既存RaceEntry、評価、予想、公開版、結果を遡及更新しない。

## 操作量

リハーサルの6頭登録は、13操作・7入力から4操作・2入力へ減少した。12レース各18頭でも、216回の個別登録ではなく、12回の貼り付け・プレビュー・確定で出走馬登録を完了できる。Identity確認と結果入力は引き続き別工程である。

## 検証

- Domain unit: カンマ／タブ、重複、不正値、18頭上限。
- Integration: 18頭登録、冪等再送、同名候補、revision、監査、既存馬番との競合、トランザクション境界。
- E2E: desktop/mobileで18頭の貼り付け、確定前に未保存、確定後のRaceEntry/Identity、スマートフォン横幅。
- JRA-VAN、外部AI、外部HTTP通信は使用しない。
- DB migrationはない。
