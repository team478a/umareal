# 銀行振込運用

## 目的

新しいカード決済会社の導入まで、銀行振込で1日利用と月額相当の有限期間閲覧を提供する。銀行振込はカード定期課金の代替契約ではなく、管理者が実際の着金を確認して初めて権限を付与する独立した決済方式とする。

## 安全境界

- 配備設定は `BILLING_TRANSPORT=bank_transfer`、管理画面の受付設定は初期値OFFとする。両方が有効な場合だけ新規申込を受け付ける。
- 会員の「振込済み」報告だけでは権限を付与しない。ADMIN+AAL2が入出金明細、識別番号、振込名義、金額、着金日時を照合する。
- 確認額が申込時の固定金額と一致しない場合、期限後の着金、未来日時は承認しない。
- 月額相当利用は有限期間の `Entitlement` とし、`Subscription` や自動課金・自動更新を作らない。既存Stripe契約は変更しない。
- 1日利用は既存 `DayPass` と同じ開始・終了・閲覧判定を使用する。
- 申込時に金額と振込先をsnapshot保存する。後日の料金・口座設定変更で既存申込を変更しない。
- 確認済み・却下済みの申込はDB triggerで更新・削除・truncateを拒否する。

## 会員フロー

1. 料金画面でプランまたは対象開催日を選ぶ。
2. 申込後に振込先、金額、期限、識別番号 `UM-XXXXXXXXXX` を確認する。
3. 振込後、マイページで振込名義を報告する。
4. 運営の着金確認後に権限が開始する。確認前は有料コンテンツへアクセスできない。

## 管理フロー

1. `/admin/billing` で口座、受付期限、月額相当の利用日数、会員向け案内を設定する。
2. 変更理由を入力し、受付を有効化する。
3. 会員の報告と銀行明細を照合する。
4. 正確な着金額と着金日時を入力して承認する。不一致や確認不能時は理由を付けて却下する。
5. 付与された有限期間権限または1日利用を同画面と監査ログで確認する。

## 配備手順

1. コードとadditive migrationを通常の承認手順で配備する。
2. APIの `BILLING_TRANSPORT` を `bank_transfer` に変更する。Stripe秘密鍵は銀行振込の起動条件にしない。
3. ADMIN+AAL2で口座情報を入力する。口座番号を含むため、管理画面共有・スクリーンショットの扱いに注意する。
4. 管理設定の受付を有効化する。
5. 少額の実振込で、申込、報告、着金照合、権限開始、期限終了を確認してから一般案内する。

停止時は管理設定の受付をOFFにする。既存の確認待ち申込と付与済み権限は削除・取消ししない。

## 初期対象外

- 振込の自動照合、銀行API接続
- 振込手数料の自動精算、差額承認、部分入金
- 自動返金
- 銀行振込へのクーポン適用
- 自動更新・継続課金
