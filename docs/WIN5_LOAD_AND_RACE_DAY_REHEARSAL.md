# WIN5負荷試験・開催日リハーサル手順

## 目的

WIN5公開前に、同時閲覧で情報境界を崩さないこと、公開ボタンの重複操作で複数の初版を作らないこと、前日準備から結果確定まで運営担当者が継続できることを確認する。

## 自動検証

### 公開操作と権限境界

PostgreSQLを使う統合試験で次を検証する。

- 同じ公開前確認IDへ8件同時に公開要求しても、初版と通知イベントは各1件だけ作られる。
- 残りの要求は成功済みの同じ公開版を返し、訂正版を誤作成しない。
- 匿名一覧、無料会員のメタデータ、有料会員の全文を各30件並列で読み、すべて成功する。
- 並列閲覧中も無料会員は`METADATA`、権利が有効な会員だけが`FULL`のままである。

実行コマンド:

```powershell
pnpm test:integration -- tests/win5.integration.test.ts tests/win5-security.integration.test.ts
```

### 任意環境への読取専用負荷試験

この試験は公開・訂正・通知などの書き込みを行わない。まずステージング環境で実行し、本番では事前に時間帯と監視担当を決める。

```powershell
$env:WIN5_LOAD_BASE_URL = "https://staging.example.com/api/v1"
$env:WIN5_LOAD_PRODUCT_ID = "公開済み商品のUUID"
$env:WIN5_LOAD_REQUESTS = "1000"
$env:WIN5_LOAD_CONCURRENCY = "50"
$env:WIN5_LOAD_P95_MS = "750"
$env:WIN5_LOAD_ERROR_RATE = "0"
pnpm win5:load-test
```

有料本文も測定する場合だけ、テスト会員のセッションCookieを`WIN5_LOAD_COOKIE`へ一時設定する。値はログ、議事録、PRへ記載しない。試験後は環境変数を削除し、テスト会員をログアウトする。

合格条件はHTTPエラー率0%、p95が750ms以下を初期値とする。Renderのインスタンス構成や実測トラフィックが確定したら、同時数と閾値を記録して更新する。

## 開催日リハーサル

対象日は本番レース日と異なるステージング用の日付を使用する。管理者と予想担当者を別アカウントにし、スマートフォンとPCを1台ずつ使う。

### 前日

1. `/admin/readiness`で公開停止、DB、通知、担当者継続性にブロックがないことを確認する。
2. WIN5管理画面で対象日、担当者、公開予定時刻、信頼度、公開範囲を設定する。
3. 対象5レース、中心馬、相手候補、評価理由、展開見解、短評、全体総評を保存する。
4. 別端末で公開前確認を開き、対象日、5レース、馬名、公開範囲を読み合わせる。
5. 初版を公開し、公開履歴がv1、通知イベントが1件であることを確認する。
6. 匿名・無料会員には馬名や理由が表示されず、有効な月額会員と対象日の1日利用だけに全文が表示されることを確認する。
7. LINEとメールには本文を含めず、安全なサイト内リンクだけが届くことを確認する。

### 当日

1. `/admin/operations?date=YYYY-MM-DD`を開き、各レースの`nextStep`と警告を確認する。
2. パドック評価を入力し、未入力頭数が0になることを確認する。
3. 最終予想をプレビューし、発走時刻前に公開する。
4. 通知が`SENT`または通知対象なしの`SKIPPED`になるまで確認する。`FAILED`は障害対応画面で確認し、原因を記録して再送する。
5. 訂正を1回実施し、理由、v2、前版への参照、訂正通知を確認する。
6. 発走後に結果を取り込み、5レース分の評価結果を確認して確定する。
7. 公開結果画面に確定済み評価だけが表示され、買い目、払戻、回収率を誤って表示しないことを確認する。

### 異常系

- 公開ボタンを2端末で同時に押し、初版が1件だけになる。
- 公開前確認後に下書きを変更し、古い確認IDが`WIN5_STALE_PREVIEW`で拒否される。
- 無料会員、有効期限切れ会員、提供対象外プランで本文が取得できない。
- 通知を試験的に失敗させ、運用アラート、確認、再送、解決まで記録できる。
- 予想公開を緊急停止し、公開が拒否され、解除後に再確認して公開できる。

## 証跡

リハーサルごとに次を残す。Cookie、トークン、メールアドレス、LINE subject、予想本文は保存しない。

- 実施日時、対象環境、対象日
- 参加者の役割（個人情報ではなく管理者、予想担当、確認者）
- GitコミットSHAとRenderリリースID
- 負荷試験の件数、同時数、p50、p95、最大値、エラー率
- 各手順の合否と、失敗時のrequest ID
- 未解決事項、担当、期限

## 本番移行判定

自動試験、ステージング負荷試験、開催日リハーサルがすべて合格し、重大・高重要度の未解決事項が0件の場合だけ本番配備候補とする。本番配備は別承認で実施する。
