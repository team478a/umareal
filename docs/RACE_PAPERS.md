# 通常レース前日紙面

## 今回の範囲

複数の通常レースの原稿を貼り付け、登録済みレース・出走馬と照合し、公開前確認を経て会員ページへ掲載する。WIN5紙面とパドック直前予想は変更しない。AIによる予想生成、買い目、購入金額、購入操作は提供しない。

公開範囲は紙面単位で「登録会員全員（無料会員を含む）」または「有料会員・対象日の1日利用者」を明示的に選ぶ。未認証者には紙面一覧・本文とも返さない。登録会員向け紙面だけは、運営者が公開範囲を選んだ馬評価を無料会員にも提供する。既存のパドック・WIN5の無料会員向け本文制限は維持する。

## 作成・公開の手順

1. レース担当がレース管理で対象日のレース名、発走時刻、出走馬番・馬名を登録する。予想担当が作成する場合は対象レースを割り当てる。
2. 管理者・レース担当は `/admin/papers`、予想担当は `/expert/papers` を二段階認証後に開く。
3. 対象日、タイトル、公開範囲、任意の総評を入力し、原稿を貼り付ける。
4. 「原稿を読み取り・照合」で紙面を確認する。一致しないレース名・馬名、未登録馬、出走取消馬、重複馬番、不明な行は自動補完せずエラーにする。
5. 保存理由を入力して下書きを保存する。この段階では会員には見えない。
6. 「紙面の公開内容を確認」で本文、公開範囲、締切、通知文面を確認する。
7. 「紙面を公開する」で公開版と通知イベントを一つのトランザクションで作る。
8. 会員はホームの新着、通常レース紙面一覧 `/papers`、お知らせから `/papers/:id` を開く。

原稿形式は競馬場名、`9R 八ヶ岳特別`、`◎4・フィールドノート`の順。東京・京都等は既存の中央競馬場一覧に従う。全角数字、○/◯、✕/×/✖を正規化し、同じレースの複数の△は保持する。原稿は20,000文字、1〜12レース、各レース1〜18頭、◎は各レース1頭。レース名の末尾C/カップは照合時のみ同じものとして扱う。馬名・発走時刻の表示は登録データを正とする。

**✕は原稿の推奨印であり、危険馬へ変換しない。** 原稿にない信頼度、選定理由、展開見解を生成しない。APIでは任意の馬別理由も保存できるが、V1画面は貼り付け原稿と任意総評を扱う。

## 権限と訂正

- 作成・下書き・確認・初版公開はADMIN/OPERATOR/EXPERT+AAL2。EXPERTは全対象レースと過去公開版の全対象レースの担当割当を満たす必要がある。
- 訂正は既存の `predictionCorrectionPolicy` に従う。既定ではADMINだけ、`EXPERT_OR_ADMIN`では担当EXPERTも可能。OPERATORへ訂正権限は追加しない。
- 訂正理由必須、新しい版を追加し、旧版・公開者・公開時刻・訂正理由を保持する。会員画面で版を切り替えられる。公開済み本文の更新・削除・TRUNCATEはPostgreSQLでも拒否する。
- 締切は現在と過去の全対象レースの最早発走時刻、および既に保存した締切の最早値。早いレースを外す・遅らせるだけでは訂正期限を開き直せない。確定・取消レースを含む紙面は公開不可。遅延レースは既存の遅延公開設定に従う。
- 公開前確認は15分。下書き・レース・馬・割当・公開版の変更後は再確認が必要。同じ確認の並行送信・再送は公開版・通知・監査を増やさない。

## データとAPI

`race_papers`: 可変の下書きJSON、revision、更新者と時刻。

`race_paper_versions`: 不変の公開JSON、公開範囲、対象日、版、締切、公開者・時刻、訂正理由。`(paperId, version)`一意。

`race_paper_previews`: 確認者、基準ハッシュ、版、訂正理由、期限、確定した公開版ID。

`notification_events.paperVersionId`: 公開版ごとに一意の通知対象。既存イベントへのnullable列追加であり、既存データの削除・変換はしない。

共有公開Contractは `packages/domain/src/race-paper.ts`。PrismaモデルをWebへ公開しない。

| API（`/api/v1`以下） | 用途 |
| --- | --- |
| POST `/expert/papers/import` | 原稿読み取り・登録データ照合。書き込みなし |
| GET `/expert/papers` | 保存済み下書き（最新50件を対象にEXPERTは全対象レースの担当割当で絞り込む） |
| GET `/expert/papers/:id` | 担当権限を確認した作業用紙面 |
| POST `/expert/papers/draft` | UUIDとrevision付き保存、理由必須 |
| POST `/expert/papers/:id/preview` | 公開内容確認 |
| POST `/expert/papers/:id/publish/:previewId` | 確認済み内容の公開・再送冪等 |
| GET `/papers?page=1` | 認証会員向け公開メタデータ（20件/ページ） |
| GET `/papers/:id` | 公開版一覧（最新50版）。権限がない版はsnapshotと訂正理由を返さない |

有料紙面は既存 `Entitlement` と `canReadPrediction` を再利用する。月額は全対象日、1日利用は一致する対象日だけ。スタッフの有料本文確認もサーバーロール・AAL2・担当割当を確認する。

## 通知と運用上の制限

初版・訂正版で既存通知イベントへ `RACE_PAPER_PUBLISHED` / `RACE_PAPER_CORRECTED` を追加する。LINE・メールは既存worker、配信設定、会員の受信設定、配送冪等キー・再送を再利用する。訂正版は訂正通知設定に従う。通知と会員のお知らせにはタイトル・対象日・版・会員ページへのリンクだけを掲載し、snapshotを読まない。タイトルや総評へ個人情報を入力しない。

`FREE_REGISTRATION`モードでも、API・workerの通知transportと管理スイッチを有効にすると無料会員へLINE公開通知を配送する。初期transportは`disabled`で、設定を変更するまで実送信しない。画面の公開成功は紙面掲載と通知イベント登録を意味し、外部配送の成功ではない。LINEからの未ログインアクセスはログイン後に紙面一覧へ戻す。

今回、結果集計・成績画面への通常紙面の追加、紙面予約公開、PDF生成、LINEリッチメニューの変更は行わない。通常紙面の印を既存パドックの最終評価へ混ぜない。公開履歴は保存するため、後続フェーズで結果評価を追加できる。

## 検証と本番適用

単体テストでは依頼された東京3レース・京都2レースの25頭を含む原稿、記号正規化、重複、買い目等の不明行拒否、本文を含めない通知・lockedレスポンスを検証する。

DB/API統合テストでは担当・AAL2・会員制限、照合失敗、未公開制限、並行公開と再送、古い確認、取消馬、有料本文のAPI除外、既存日付付き閲覧権、訂正版・旧版保持、DB不変性・締切、停止設定、LINE/メール配送を検証する。Playwrightはdesktop/mobileで取り込み→保存→確認→初版→訂正→未登録者制限→無料会員本文→通知リンクと横スクロールを確認する。

本番適用は別フェーズ。マージ後、非破壊migration `202610020001_regular_race_paper` を適用してAPI・Web・workerの同一リリースを配備する。実LINE/メール配送・実機の確認、および原稿の対象日・公式出走表・発走時刻の確認をしてから担当者が公開する。ユーザーが提示した「明日」は実装時の日付へ自動変換して公開しない。
