# Phase 5M 退会・個人情報管理

## 実装範囲

MEMBER本人はマイページで退会条件を確認し、理由、確認文言「退会する」、設定済みの場合は現在のパスワードを入力して利用を停止できる。有効期間中の月額契約または1日利用がある場合は処理せず、解約予約または利用期間終了を案内する。スタッフアカウントは本人向け画面から停止できない。

退会処理は一つのDBトランザクションで、`users.disabledAt` の設定、全セッション削除、通知設定の全停止、LINE連携解除、現在・将来の閲覧権限失効、未使用のメール確認・パスワード再設定・LINE OAuthフローの消費、監査ログと退会記録の追記を行う。ログイン処理と通知ワーカーは既存の `disabledAt` 再確認により以後の利用・配信を拒否する。

`account_closures` は会員ごとに一件だけ作成でき、DBトリガーがUPDATE、DELETE、TRUNCATEを拒否する。管理者はAAL2完了後に `/admin/account-closures` で処理結果を確認できる。APIはパスワードハッシュ、認証秘密、トークンを返さない。

## データ保持

このフェーズでは物理削除や匿名化を行わない。公開・評価履歴との関係、支払・契約履歴、同意履歴、監査履歴を保持する。正式な保持期間、匿名化対象、法令・問い合わせ対応、再登録時の扱いが未決定のため、開発用保持方針を `development-v1` として記録する。

## 本番との境界

外部決済の契約終了、返金、LINEプロバイダー側のデータ削除、Supabase Authユーザー削除、本人からの開示・削除請求ワークフローは含まない。本番前に正式なプライバシーポリシーと保持期間を確定し、履歴を壊さず識別情報を匿名化する別工程が必要になる。
