# Phase 5M 退会・個人情報管理

## 実装範囲

MEMBER本人はマイページで退会条件を確認し、理由、確認文言「退会する」、設定済みの場合は現在のパスワードを入力して利用を停止できる。有効期間中の月額契約または1日利用がある場合は処理せず、解約予約または利用期間終了を案内する。スタッフアカウントは本人向け画面から停止できない。

退会処理は一つのDBトランザクションで、`users.disabledAt` の設定、全セッション削除、通知設定の全停止、LINE連携解除、現在・将来の閲覧権限失効、未使用のメール確認・パスワード再設定・LINE OAuthフローの消費、監査ログと退会記録の追記を行う。ログイン処理と通知ワーカーは既存の `disabledAt` 再確認により以後の利用・配信を拒否する。

`account_closures` は会員ごとに一件だけ作成でき、DBトリガーがUPDATE、DELETE、TRUNCATEを拒否する。管理者はAAL2完了後に `/admin/account-closures` で処理結果を確認できる。APIはパスワードハッシュ、認証秘密、トークンを返さない。

## データ保持

このフェーズでは物理削除や匿名化を行わない。公開・評価履歴との関係、支払・契約履歴、同意履歴、監査履歴を保持する。正式な保持期間、匿名化対象、法令・問い合わせ対応、再登録時の扱いが未決定のため、開発用保持方針を `development-v1` として記録する。

### 正式方針の追記承認

管理者はAAL2完了後、`/admin/account-closures` で方針version、識別情報とネットワーク識別子の保持日数、匿名化対象、再登録時の扱い、法務確認参照、変更理由を記録できる。記録は既存の追記専用監査ログへ `DATA_RETENTION_POLICY_APPROVED` として保存し、同じversionの再利用を拒否する。以後の退会記録は、その時点の最新かつ構造検証済み方針versionへ固定する。既存退会記録のversionは変更しない。

管理画面は現在の承認versionと一致し、保持期限へ到達した退会記録数をドライラン表示するが、匿名化や物理削除は実行しない。`development-v1`や別versionの過去記録へ最新方針を遡及適用せず、方針未対応件数として分離する。正式方針が記録されるまで `development-v1` を維持する。Readinessは正式方針の記録後も、自動匿名化の実装・法務確認・復元不能性試験が残るため `MANUAL` とする。

## 本番との境界

外部決済の契約終了、返金、LINEプロバイダー側のデータ削除、Supabase Authユーザー削除、本人からの開示・削除請求ワークフローは含まない。正式なプライバシーポリシーと保持期間を管理者が記録した後も、履歴を壊さず識別情報を匿名化する実行工程は別の承認対象とする。
