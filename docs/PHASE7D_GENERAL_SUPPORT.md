# Phase 7D 一般お問い合わせ管理

## 完成した動作

- 無料会員を含むMEMBER本人が、請求情報なしで一般問い合わせを送信できる。
- 種別、件名、本文、受付状態を保持し、同じIdempotency-Keyの再送は同じ受付結果を返す。
- 会員画面は本人の問い合わせと運営からの回答だけを表示し、内部対応理由、担当者、他会員の情報を返さない。
- ADMIN+AAL2とOPERATORが受付済み、確認中、回答済み、再開を理由付きで管理する。回答済みへの変更には会員向け回答を必須にする。
- 問い合わせ内容は変更・削除不可、対応イベントは追記専用としてPostgreSQLトリガーで保護する。
- 会員画面`/support`と管理画面`/admin/support`を独立させ、管理コンソールには管理機能だけを表示する。
- 回答済みイベントと通知イベントを同一DBトランザクションで作成し、PostgreSQLトリガーでも対応関係を検証する。
- 本人のWeb通知へ回答案内を表示する。メール・LINE通知は件名、問い合わせ本文、回答本文、内部理由を含めず、`/support`への導線だけを送る。
- 予想通知の購読設定や有料権限には依存せず、メール・LINEの全体停止、受信可否、配信拒否、連携状態は送信直前に再検証する。
- 会員本人が同じ問い合わせへ追加情報を送信できる。回答済みへの追加質問は受付済みに戻し、管理画面では最近更新された問い合わせを先に表示する。
- 追記はIdempotency-Keyで二重登録を防ぎ、`MEMBER_MESSAGE`イベントとして追記専用で保存する。他会員には問い合わせの存在を明かさない。
- ADMIN+AAL2またはOPERATORが、優先度、担当者、対応期限を理由付きで設定できる。担当候補は有効なADMIN/OPERATORだけをAPIが返し、DBも不正な担当者を拒否する。
- 管理一覧は未解決の期限超過、優先度、期限、最終更新の順で表示し、期限超過と緊急案件を視覚的に判別できる。振り分け履歴は`TRIAGED`イベントと監査へ追記する。
- 対応期限の24時間前を警告、期限超過を重大として運用アラートへ自動登録する。期限接近から超過へ変わった場合は新しい重大アラートを作り、解決・期限解除・期限延期では自動解決する。
- 運営向け外部通知は件名、会員情報、問い合わせ本文、回答内容を含めず、`/admin/support`への導線だけを送る。

## API

- `GET /api/v1/support/me`
- `POST /api/v1/support/requests`
- `POST /api/v1/support/requests/:id/messages`
- `GET /api/v1/admin/support?status=ALL|OPEN|IN_PROGRESS|RESOLVED`
- `POST /api/v1/admin/support/:id/status`
- `POST /api/v1/admin/support/:id/triage`
