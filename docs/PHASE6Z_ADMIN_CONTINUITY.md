# Phase 6Z 管理者の復旧と継続運用

## 完成条件

- 管理者+AAL2が、確認済みメールを持つ有効会員を理由付きで管理者へ昇格できる。
- 昇格時に対象者のローカルセッションをすべて失効し、対象者は主TOTPを確認するまで管理操作を行えない。
- Supabase認証の管理者が、AAL2確認後に主端末とは別管理の予備TOTPを登録できる。
- AAL1ログイン後に主または予備要素を選び、Supabaseが発行した`aal2` JWTで管理操作へ進める。
- 予備要素の解除は理由を必須にし、Supabaseとローカルの全セッションを失効して監査へ追記する。
- 本番準備画面と専用管理画面で、管理者2名以上、各管理者の主・予備要素を確認できる。

## セキュリティ境界

Supabase Authは利用者向けMFA復旧コードをサポートしないため、アプリ独自コードは発行しない。自社DBには主・予備のProvider factor IDと15分有効の登録途中状態だけを保存し、TOTP secretは保存しない。管理権限は従来どおり、Supabaseが署名したJWTの`aal=aal2`と自社DBのロールを両方満たした場合だけ付与する。

予備要素の登録完了時はSupabaseが他のセッションを失効する。予備要素を解除した場合はProviderのglobal logoutを実行し、自社DBのローカルセッションも削除する。Providerの応答本文、TOTP secret、アクセストークン、更新トークンは監査やログへ保存しない。

## 運用手順

1. 既存管理者がAAL2を完了し、`/admin/continuity`を開く。
2. 本人確認済みの候補者を選び、画面に表示されたメールアドレスを再入力し、昇格理由を保存する。
3. 新管理者が再ログインし、`/security`で主認証アプリを登録する。
4. AAL2完了後、同じ画面で別端末または別管理の認証アプリを予備要素として登録する。
5. 両管理者について主・予備が準備済みとなり、`/admin/readiness`の「管理者の継続運用」が確認済みになることを確認する。

予備端末を交換する場合は、主要素でAAL2を完了し、理由付きで予備要素を解除する。全端末からログアウトされるため、再ログイン後に新しい予備要素を登録する。主・予備の両方を失った場合にservice-role keyで解除する機能は実装していないため、2名目の管理者を先に準備する。

Supabase実環境での主・予備要素登録、別端末ログイン、解除後の全セッション失効は、本番接続時に管理者立会いで確認する。
