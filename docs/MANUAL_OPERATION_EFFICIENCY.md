# JRA-VAN未接続 実運用効率化

作成日: 2026-10-07

## 対象

実運用リハーサルで確認した反復入力のうち、DB変更なしで安全に削減できる出走馬登録、暫定Horse Identity確認、パドック6項目入力を対象とする。

## 実装内容

- 暫定Identity一覧を選択中の開催日で絞り込み、さらにレース単位でも絞り込めるようにした。
- 暫定馬ごとに競馬場、レース番号、馬番を表示し、確認対象を識別しやすくした。
- 共通のIdentity確認理由を各馬へ再利用できるようにした。個別理由がある場合は馬ごとに上書きできる。
- 簡易出走馬登録の理由を登録後も保持し、同じ出馬表から連続登録する際の再入力を不要にした。
- 出走馬保存後に暫定Identity一覧を自動更新する。
- 1レース最大18頭の`馬番,馬名`を貼り付け、全頭プレビュー後に1回で確定できる確認付き一括簡易登録を追加した。
- 一括登録は18頭のHorse、暫定Identity、RaceEntry、revision、監査を同一トランザクションで保存し、一部成功を許可しない。
- 対象レース内で同名候補がない暫定馬を選択し、一覧と共通理由を確認して最大18頭を1回で別馬として確定できるようにした。
- 一括確定時は候補、レース所属、Horse ID、更新時刻をサーバーで再確認し、1件でも変化があれば全件を反映しない。監査は従来どおり馬ごとに残す。
- 現在の1頭について5つのパドック指標を同じ値または判断不能へ1操作で設定し、異なる項目は従来の個別ボタンで調整できるようにした。総合変化と短評はまとめず、担当者の明示判断を維持する。
- レース一括登録と出走馬一括簡易登録の未送信内容を、利用者・対象レースで分離した同一タブ内の下書きとして復元できるようにした。登録成功または明示破棄で削除し、previewは必ず作り直す。
- 結果のかんたん一括入力も、利用者・対象レース・結果下書きrevisionで分離して復元する。反映成功または明示破棄で削除し、結果差分previewは必ず作り直す。

## 安全境界

- 同名候補があるIdentityは従来どおり馬ごとの明示操作を必要とする。候補なしの一括確定も、対象選択・一覧確認・理由入力を必須にし、監査記録は馬ごとに保存する。
- 同名馬を自動mergeしない。
- 既存RaceEntry、Assessment、Prediction、公開版、結果を遡及更新しない。
- パドックまとめ入力は現在の馬だけを対象とし、次の馬への引継ぎ、複数馬の自動評価、初期値の推測を行わない。
- DB migration、外部データ通信、外部AI通信は行わない。

## 操作量

6頭の一括簡易登録は13操作・7入力から4操作・2入力へ削減した。候補なし6頭のIdentity確認は8操作・1入力から5操作・1入力へ削減した。パドック6頭は6指標を個別に押す55操作相当から、6項目まとめ入力を使う25操作へ削減した。結果入力を含む実運用E2E上の合計は87操作・90入力項目。12レース各18頭の出走馬登録と候補なしIdentityは、レースごとの貼り付け・確認・一括確定で処理できる。同名候補と、馬ごとに異なるパドック所見は個別判断を維持する。
